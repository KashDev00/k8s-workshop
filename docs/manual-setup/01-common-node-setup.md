# Step 01: Common Node Preparation

**Playbook Reference:** `ansible/playbook_common.yaml`  
**Target Nodes:** All 6 Kubernetes nodes (`controlplane-0`, `controlplane-1`, `controlplane-2`, `worker-0`, `worker-1`, `worker-2`)

Before Kubernetes can be initialized or joined, every node must be prepared with the correct kernel modules, networking rules, container runtime (`containerd`), and Kubernetes CLI/agent packages (`kubeadm`, `kubelet`, `kubectl`).

> [!TIP]
> **Want to understand the Linux science behind these commands?** Read **[Step 00: Linux Fundamentals & Kernel Prerequisites](00-linux-prerequisites-for-kubernetes.md)** for deep-dive explanations on `overlay`, `br_netfilter`, IP forwarding, swap disabling, and cgroup drivers.

Repeat the following instructions on **all 6 Kubernetes nodes**.

---

## 🔌 Before You Begin: Finding IPs & Connecting via SSH

1. **Find your VM IP addresses:** After running `terraform apply`, check your Ansible inventory file from the project root to find the IP address of each node:
   ```bash
   cat ansible/inventory_all.ini
   ```
2. **Connect via SSH:** Open 6 terminal tabs (or a tmux session) and SSH into each Kubernetes node (`controlplane-0...2`, `worker-0...2`) using the SSH key generated by Terraform:
   ```bash
   ssh -i secrets/private_key.pem ubuntu@<VM_IP_ADDRESS>
   ```
3. **Resetting a Node:** If you ever make a mistake during practice, you don't need to re-run Terraform! Clean the node by running:
   ```bash
   sudo kubeadm reset -f
   sudo rm -rf /etc/kubernetes/admin.conf /etc/kubernetes/pki $HOME/.kube/config
   ```

## 1. Wait for Cloud-Init and Package Locks

- **What this step does:** Pauses execution until OpenStack's `cloud-init` startup sequence finishes and loops until Linux package manager lock files (`/var/lib/dpkg/lock`, `/var/lib/apt/lists/lock`) are freed by background system processes.
- **Why we are doing it:** When VMs boot in OpenStack, cloud-init scripts and Ubuntu unattended upgrades run automatically in the background. If you attempt to install `apt` packages while these background scripts hold dpkg/apt locks, your installation will fail immediately or corrupt the package database.

```bash
# 1. Wait for cloud-init to complete all boot scripts
cloud-init status --wait

# 2. Wait until apt/dpkg lock files are released
while fuser /var/lib/dpkg/lock >/dev/null 2>&1 || \
      fuser /var/lib/dpkg/lock-frontend >/dev/null 2>&1 || \
      fuser /var/lib/apt/lists/lock >/dev/null 2>&1; do
  echo "Waiting for apt/dpkg locks to release..."
  sleep 5
done
```

## 2. Hostname Synchronization via OpenStack Metadata API

- **What this step does:** Queries the local OpenStack Metadata HTTP service (`169.254.169.254`) to get the VM's cloud instance name and applies it as the Linux system hostname using `hostnamectl set-hostname`.
- **Why we are doing it:** OpenStack instances can sometimes boot with generic DHCP hostnames instead of their designated cloud names. Kubernetes relies strictly on the hostname for node identification, TLS certificate generation, and intra-node authentication. Synchronizing the OS hostname with the cloud instance name prevents certificate SAN (Subject Alternative Name) mismatches and duplicate node registration errors.

```bash
# 1. Query the OpenStack Link-Local Metadata Service (169.254.169.254)
OS_HOSTNAME=$(curl -s http://169.254.169.254/latest/meta-data/hostname | cut -d. -f1)
echo "OpenStack Instance Hostname is: ${OS_HOSTNAME}"

# 2. Set the OS hostname immediately
sudo hostnamectl set-hostname "${OS_HOSTNAME}"
```

## 3. Disable Swap Storage

- **What this step does:** Turns off active Linux swap memory immediately with `swapoff -a` and comments out swap filesystem entries in `/etc/fstab` so swap remains disabled permanently across reboots.
- **Why we are doing it:** Kubernetes requires swap memory to be disabled. When swap is enabled, the Linux kernel can page container memory to disk without the Kubernetes scheduler knowing. This breaks `kubelet`'s ability to accurately calculate memory limits, enforce pod QoS (Quality of Service) guarantees, and trigger OOM (Out Of Memory) evictions correctly.

```bash
# 1. Turn off active swap immediately
sudo swapoff -a

# 2. Comment out any swap mount entries in /etc/fstab so it remains disabled after reboot
sudo sed -i '/ swap / s/^\(.*\)$/#\1/g' /etc/fstab
```

## 4. Kernel Modules & Networking Sysctl Configuration

- **What this step does:** Configures Linux to load the `overlay` and `br_netfilter` kernel modules on boot (`/etc/modules-load.d/k8s.conf`), loads them immediately (`modprobe`), and sets network kernel parameters (`/etc/sysctl.d/k8s.conf`) to enable bridge filtering and IPv4 forwarding.
- **Why we are doing it:** 
  - `overlay` kernel module: Required by the container runtime (`containerd`) to create layered container filesystems (OverlayFS).
  - `br_netfilter` kernel module: Enables Linux bridge interfaces to pass traffic through firewall (`iptables`) rules, which is required for Kubernetes Services and network policies to intercept and route pod packets.
  - `net.ipv4.ip_forward = 1`: Allows Linux to act as a router, forwarding IP packets between Pods located on different nodes or subnets.
  - `bridge-nf-call-iptables = 1`: Ensures bridged IPv4 traffic is evaluated by iptables rules.

```bash
# 1. Create a configuration file to load kernel modules on boot
cat <<EOF | sudo tee /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF
```
```bash
# 2. Load the modules explicitly into the running kernel
sudo modprobe overlay
sudo modprobe br_netfilter
```
```bash
# 3. Configure sysctl parameters for network bridging and IPv4 forwarding
cat <<EOF | sudo tee /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF
```
```bash
# 4. Apply the sysctl parameters without rebooting
sudo sysctl --system
```

## 5. Install and Configure Container Runtime (`containerd`)

- **What this step does:** Installs official Docker GPG keys and APT repositories, installs `containerd.io`, generates the default `/etc/containerd/config.toml`, enables `SystemdCgroup = true`, enables the CRI (Container Runtime Interface) plugin, and restarts the service.
- **Why we are doing it:** Kubernetes does not run containers directly; it delegates execution to a Container Runtime via the CRI. We use `containerd`. We must explicitly set `SystemdCgroup = true` because Ubuntu 24.04 uses `systemd` as its system init manager. If `kubelet` manages cgroups via `systemd` while `containerd` uses `cgroupfs`, two competing cgroup hierarchies will exist, leading to resource accounting bugs and node instability.

```bash
# 1. Install prerequisites
sudo apt-get update
sudo apt-get install -y apt-transport-https ca-certificates curl gnupg lsb-release socat
```
```bash
# 2. Add Docker official GPG key and APT repository
# Note: Why use /etc/apt/keyrings/ and gpg --dearmor? See Step 00 (Linux Fundamentals) for how isolated APT keyrings protect your OS.
sudo mkdir -p /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
```
```bash
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \
  $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list
```
```bash
# 3. Install containerd
sudo apt-get update
sudo apt-get install -y containerd.io
```
```bash
# 4. Generate the default containerd configuration file
sudo mkdir -p /etc/containerd
containerd config default | sudo tee /etc/containerd/config.toml > /dev/null
```
```bash
# 5. Configure containerd to use systemd cgroups and enable CRI plugin
sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml
sudo sed -i 's/^[[:space:]]*disabled_plugins = \["cri"\]/# &/' /etc/containerd/config.toml
```
```bash
# 6. Restart and enable containerd service
sudo systemctl restart containerd
sudo systemctl enable containerd
```

## 6. Install Kubernetes Components (`kubeadm`, `kubelet`, `kubectl` v1.35)

- **What this step does:** Adds the official Kubernetes v1.35 APT repository, installs `kubelet`, `kubeadm`, and `kubectl`, places a package hold (`apt-mark hold`) on them, and sets `--hostname-override` in `/etc/default/kubelet`.
- **Why we are doing it:**
  - `kubelet`: The primary node agent that runs on every node to supervise containers and communicate with the API server.
  - `kubeadm`: The administrative CLI tool that bootstraps cluster control planes and joins nodes.
  - `kubectl`: The user command-line interface for managing Kubernetes resources.
  - `apt-mark hold`: Prevents automatic Linux upgrades (`apt upgrade`) from accidentally updating Kubernetes packages, which would violate cluster version compatibility rules.
  - `--hostname-override`: Forces `kubelet` to register with the Kubernetes API server using the exact OpenStack instance hostname rather than a DHCP or DNS-derived name.

```bash
# 1. Define Kubernetes release version
K8S_VERSION="v1.35"
```
```bash
# 2. Add Kubernetes GPG signing key and APT repository
curl -fsSL "https://pkgs.k8s.io/core:/stable:/${K8S_VERSION}/deb/Release.key" | sudo gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
echo "deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/${K8S_VERSION}/deb/ /" | sudo tee /etc/apt/sources.list.d/kubernetes.list
```
```bash
# 3. Install kubeadm, kubelet, and kubectl
sudo apt-get update
sudo apt-get install -y kubelet kubeadm kubectl
```
```bash
# 4. Pin (hold) package versions so 'apt upgrade' never accidentally breaks cluster version parity
sudo apt-mark hold kubelet kubeadm kubectl
```
```bash
# 5. Configure Kubelet hostname override
OS_HOSTNAME=$(curl -s http://169.254.169.254/latest/meta-data/hostname | cut -d. -f1)
echo "KUBELET_EXTRA_ARGS=--hostname-override=${OS_HOSTNAME}" | sudo tee /etc/default/kubelet
```
```bash
# 6. Restart kubelet service
sudo systemctl restart kubelet
sudo systemctl enable kubelet
```

> [!NOTE]
> At this stage, `systemctl status kubelet` may show a crashloop waiting for a kubeconfig file (`/etc/kubernetes/kubelet.conf`). This is **normal** until the node is bootstrapped (`kubeadm init`) or joined (`kubeadm join`) in later steps.

## 7. Prepare Longhorn Storage Directory (Worker Nodes Only)

> [!IMPORTANT]
> **Only execute this step on `worker-0`, `worker-1`, and `worker-2`. Do NOT run on control plane nodes.**

- **What this step does:** Creates a dedicated directory `/data0` on the host root filesystem with permissions `755` and ownership `root:root`.
- **Why we are doing it:** Our cluster uses **Longhorn** as a cloud-native distributed block storage system. Longhorn is configured to use `/data0` as a hostPath mount point to store replicated disk images and volumes on worker nodes. Pre-creating it with root ownership ensures Longhorn's CSI storage driver can write data without permission errors.

```bash
# Create the storage directory with root ownership
sudo mkdir -p /data0
sudo chmod 755 /data0
sudo chown root:root /data0
```

## ✅ Verification Check

- **What this check does:** Validates that swap is off, IPv4 forwarding is active, `containerd` is active, and `kubeadm` is installed.
- **Why we are doing it:** Checking these prerequisites before running `kubeadm init` or `kubeadm join` catches missing kernel flags or inactive runtimes early, avoiding confusing cluster bootstrap failures.

```bash
# 1. Verify swap is disabled (should output nothing)
swapon --show
```
```bash
# 2. Verify IP forwarding is enabled (should output net.ipv4.ip_forward = 1)
sysctl net.ipv4.ip_forward
```
```bash
# 3. Verify containerd is running (should output active)
systemctl is-active containerd
```
```bash
# 4. Verify kubeadm version (should output v1.35.x)
kubeadm version
```
