# Step 03: Initial Control Plane Bootstrap

**Playbook Reference:** `ansible/playbook_controlplane_init.yaml`  
**Target Node:** Primary Control Plane Node (`controlplane-0`)

In this step, we initialize the very first node of our High Availability Kubernetes cluster (`controlplane-0`) using `kubeadm init`. We explicitly omit the default `kube-proxy` addon so that we can install **Cilium with eBPF Kube-Proxy Replacement**, along with **Gateway API v1.6.1** and the **Kubernetes Metrics Server**.

Execute the following steps **only on `controlplane-0`**.

---

## 🔌 Before You Begin: Finding IPs & Connecting via SSH

1. **Find your controlplane-0 IP address:** Check your node IPs from `ansible/inventory_all.ini`:
   ```bash
   cat ansible/inventory_all.ini
   ```
2. **Connect via SSH:** SSH into `controlplane-0` using the SSH key generated by Terraform:
   ```bash
   ssh -i secrets/private_key.pem ubuntu@<CONTROLPLANE_0_IP_ADDRESS>
   ```
3. **Resetting a Node:** If you ever make a mistake during `kubeadm init`, you can reset `controlplane-0` to try again:
   ```bash
   sudo kubeadm reset -f
   sudo rm -rf /etc/kubernetes/admin.conf /etc/kubernetes/pki $HOME/.kube/config
   ```

---

## 1. Determine Your Control Plane Endpoint

- **What this step does:** Stores the primary API server endpoint address (`IP:PORT`) into an environment variable (`FINAL_CP_ENDPOINT`) for use during cluster initialization. In this setup, this is `controlplane-0`'s own internal IP address.
- **Why we are doing it:** Kubernetes embeds this endpoint into TLS certificates and kubeconfig files. All worker nodes, secondary control planes, and `kubectl` clients will connect to this address. Setting it consistently ensures all cluster components agree on where to find the API server.

In `playbook_controlplane_init.yaml`, this value is read from the `control_plane_endpoint` variable in your Ansible inventory (which Terraform sets to `controlplane-0`'s IP). You can extract it directly:

```bash
# Extract controlplane-0's IP from Ansible inventory:
CP_IP=$(grep '^control_plane_endpoint=' ansible/inventory_all.ini | cut -d= -f2)
export FINAL_CP_ENDPOINT="${CP_IP}:6443"

# Verify the variable is set correctly
echo "Control Plane Endpoint: ${FINAL_CP_ENDPOINT}"
```

> [!TIP]
> If you are building a cluster without `ansible/inventory_all.ini`, set this to `controlplane-0`'s internal IP: `export FINAL_CP_ENDPOINT="<CONTROLPLANE_0_IP>:6443"`.

---

## 2. Initialize Kubernetes (`kubeadm init`)

- **What this step does:** Bootstraps the core Kubernetes control plane services (`kube-apiserver`, `kube-controller-manager`, `kube-scheduler`, and `etcd`) on `controlplane-0` using `kubeadm init`.
- **Why we are doing it:**
  - `--node-name="${OS_HOSTNAME}"`: Ensures Kubernetes records the node's name exactly as defined in OpenStack metadata.
  - `--control-plane-endpoint="${FINAL_CP_ENDPOINT}"`: Embeds `controlplane-0`'s IP into the API server's TLS certificate Subject Alternative Names (SANs) so all cluster nodes trust connections to that endpoint.
  - `--upload-certs`: Encrypts control plane certificates and stores them in a temporary Kubernetes Secret for 2 hours, allowing `controlplane-1` and `controlplane-2` to download them securely during HA join.
  - `--pod-network-cidr="10.0.0.0/16"`: Reserves this IP CIDR block for pod IP allocations across the cluster (must match Cilium's IPAM pool).
  - `--skip-phases=addon/kube-proxy`: Omits standard Kubernetes `kube-proxy` (iptables rules) because **Cilium eBPF** will completely replace it for superior networking performance.

```bash
# 1. Fetch OpenStack instance hostname
OS_HOSTNAME=$(curl -s http://169.254.169.254/latest/meta-data/hostname | cut -d. -f1)

# 2. Run kubeadm init
sudo kubeadm init \
  --node-name="${OS_HOSTNAME}" \
  --control-plane-endpoint="${FINAL_CP_ENDPOINT}" \
  --upload-certs \
  --pod-network-cidr="10.0.0.0/16" \
  --skip-token-print \
  --skip-phases=addon/kube-proxy
```

## 3. Configure `kubectl` for the `ubuntu` User

- **What this step does:** Creates the `$HOME/.kube` directory, copies the generated Kubernetes administrator configuration (`/etc/kubernetes/admin.conf`) to `$HOME/.kube/config`, and changes file ownership to the `ubuntu` user.
- **Why we are doing it:** By default, `/etc/kubernetes/admin.conf` is owned by `root`. Copying it to the `ubuntu` user's home directory allows you to run `kubectl` commands without prefixing every command with `sudo`.

```bash
mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config

# Test your access
kubectl get nodes -o wide
```

> [!NOTE]
> Your node `controlplane-0` will appear in a `NotReady` state. This is **expected** because no CNI (Container Network Interface) plugin is installed yet.

## 4. Customizing & Fetching `kubeconfig` to Local Workstation (Optional)

- **What this step does:** In `playbook_controlplane_init.yaml`, Ansible fetches `/etc/kubernetes/admin.conf` from `controlplane-0` to your local workstation at `kubeconfigs/stfc-cloud.kubeconfig` and renames generic cluster/user/context identifiers (`kubernetes-admin@kubernetes`) to workshop-specific names (`stfc-cloud`, `stfc-cloud-admin`).
- **Why we are doing it:** When managing multiple Kubernetes clusters from your local laptop, generic names like `kubernetes-admin@kubernetes` cause context collisions. Renaming them allows you to safely merge this kubeconfig into your local `~/.kube/config`.

If you want to manage the cluster from your **local machine / laptop**, run these commands from your local repository root:

```bash
# 1. Fetch admin.conf from controlplane-0 to your local kubeconfigs folder
mkdir -p kubeconfigs
scp -i secrets/private_key.pem ubuntu@<CONTROLPLANE_0_IP>:/etc/kubernetes/admin.conf kubeconfigs/stfc-cloud.kubeconfig

# 2. Rename cluster, user, and context names
KUBECONFIG="kubeconfigs/stfc-cloud.kubeconfig"
sed -i 's|name: kubernetes$|name: stfc-cloud|g' "$KUBECONFIG"
sed -i 's|cluster: kubernetes$|cluster: stfc-cloud|g' "$KUBECONFIG"
sed -i 's|name: kubernetes-admin$|name: stfc-cloud-admin|g' "$KUBECONFIG"
sed -i 's|user: kubernetes-admin$|user: stfc-cloud-admin|g' "$KUBECONFIG"
sed -i 's|name: kubernetes-admin@kubernetes$|name: stfc-cloud-admin@stfc-cloud|g' "$KUBECONFIG"
sed -i 's|current-context: kubernetes-admin@kubernetes$|current-context: stfc-cloud-admin@stfc-cloud|g' "$KUBECONFIG"
```

## 5. Install Helm v3 Package Manager

- **What this step does:** Downloads and runs the official Helm 3 installer script (`get-helm-3`) to install the `helm` binary into `/usr/local/bin/helm`.
- **Why we are doing it:** Helm is the standard package manager for Kubernetes. We need Helm to deploy complex CNI and observability charts (Cilium and Metrics Server) with reproducible configurations.

```bash
curl -fsSL https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 | bash
helm version
```

---

## 6. Install Kubernetes Gateway API v1.6.1 CRDs

- **What this step does:** Applies official Kubernetes Gateway API Custom Resource Definitions (CRDs) version 1.6.1 directly from the upstream repository.
- **Why we are doing it:** The **Gateway API** is the modern Kubernetes standard for Layer 4/Layer 7 traffic routing, replacing the older `Ingress` API. We must apply Gateway API CRDs **before** installing Cilium so that Cilium's Gateway API controller detects the schemas and registers itself as an accepted GatewayClass (`cilium`).

```bash
kubectl apply --server-side -f https://github.com/kubernetes-sigs/gateway-api/releases/download/v1.6.1/standard-install.yaml

# Verify Gateway API CRDs are installed
kubectl get crd | grep gateway.networking.k8s.io
```

---

## 7. Install Cilium CNI with Gateway API & Kube-Proxy Replacement

- **What this step does:** Adds the official Cilium Helm repository and installs the `cilium/cilium` chart into the `kube-system` namespace with eBPF Kube-Proxy Replacement, Gateway API controller support, and Hubble observability enabled.
- **Why we are doing it:**
  - `k8sServiceHost` & `k8sServicePort`: Tells Cilium where to reach the Kubernetes API directly without relying on default `kube-proxy` iptables rules.
  - `gatewayAPI.enabled=true`: Enables Cilium's built-in Gateway API controller to route ingress HTTP requests.
  - `ipam.operator.clusterPoolIPv4PodCIDRList='{10.0.0.0/16}'`: Configures Cilium's IPAM (IP Address Management) pool to assign pod IPs from the CIDR block reserved in Step 2.
  - `kubeProxyReplacement=true`: Enables eBPF-based load balancing for Kubernetes Services (`ClusterIP`, `NodePort`, `LoadBalancer`), providing lower latency and lower CPU overhead than iptables.
  - `hubble.relay.enabled=true` & `hubble.ui.enabled=true`: Deploys Hubble, Cilium's eBPF-based observability and network flow inspection platform.

```bash
# 1. Add Cilium Helm repository
helm repo add cilium https://helm.cilium.io/
helm repo update

# 2. Extract the API server IP (without port 6443) for Cilium configuration
K8S_SERVICE_HOST=$(echo "${FINAL_CP_ENDPOINT}" | cut -d: -f1)

# 3. Install Cilium
helm install cilium cilium/cilium \
  --namespace kube-system \
  --set cluster.id=1 \
  --set cluster.name=stfc-cloud \
  --set k8sServiceHost="${K8S_SERVICE_HOST}" \
  --set k8sServicePort=6443 \
  --set gatewayAPI.enabled=true \
  --set ipam.operator.clusterPoolIPv4PodCIDRList='{10.0.0.0/16}' \
  --set kubeProxyReplacement=true \
  --set hubble.relay.enabled=true \
  --set hubble.ui.enabled=true
```

## 8. Install Kubernetes Metrics Server

- **What this step does:** Adds the official Kubernetes-Sigs Helm repository and deploys the `metrics-server` chart into `kube-system` with explicit kubelet TLS flags.
- **Why we are doing it:** The **Metrics Server** collects CPU and memory usage statistics from `kubelet` on each node. It powers diagnostic commands like `kubectl top node` / `kubectl top pod` and enables Horizontal Pod Autoscalers (HPA).
  - `--kubelet-insecure-tls`: Required because `kubelet` TLS certificates are self-signed and may not match Internal IP addresses or custom OpenStack hostnames by default.
  - `--kubelet-preferred-address-types=InternalIP`: Forces Metrics Server to contact kubelets via internal OpenStack IPs rather than unresolvable external DNS names.

```bash
# 1. Add Metrics Server Helm repository
helm repo add metrics-server https://kubernetes-sigs.github.io/metrics-server/
helm repo update

# 2. Install Metrics Server
helm install metrics-server metrics-server/metrics-server \
  --namespace kube-system \
  --set args='{--kubelet-insecure-tls,--kubelet-preferred-address-types=InternalIP}'
```

## ✅ Verification Check

- **What this check does:** Validates that `controlplane-0` has transitioned from `NotReady` to `Ready`, all core system pods are `Running`, and the `cilium` GatewayClass is registered.
- **Why we are doing it:** Confirming that the primary control plane node is healthy and Cilium CNI is active ensures that subsequent control plane nodes and worker nodes can join without networking failures.

```bash
# 1. Check node readiness (controlplane-0 should transition to Ready!)
kubectl get nodes -o wide

# 2. Check that Cilium and Metrics Server pods are Running
kubectl get pods -n kube-system

# 3. Check that GatewayClass 'cilium' is available
kubectl get gatewayclass
```
